`v` is a terminal tool for coding together with an AI agent: you and the agent take turns editing the same code.

What works now:

- an omnibox with commands: type `/` for a menu that filters as you type; Tab, Shift-Tab and arrows move the selection, Enter picks it;
- workdir defaults to the directory where `v` was launched. Start with `v /path/to/project` or `v -C /path/to/project` (`--workdir` also works); `/workdir` opens a directory list: → enters the highlighted folder, ← goes up (and highlights the folder you left), Enter chooses it; `/workdir <directory>` changes it directly, and `/workdir` shows the current path. The agent and conversation are kept when changing workdir;
- `/open [path]` stays in the omnibox and lists workdir (or the path's directory) in the main area; typing fuzzy-filters names, ↑↓ select, → enters a folder or opens a file, ← goes up, Enter opens (a name with no match is created empty); files open with syntax highlighting;
- in windows at least 100 columns wide, `/open`, `/workdir`, `/switch` and `/show` add a read-only preview on the right: a highlighted file or a folder's contents, a branch's recent commits, or the selected commit's message and patch. Shift-↑↓ or the mouse wheel over it scroll the preview;
- `/show` opens the current branch's history (last 500 commits); once it is open, typing in the omnibox searches hash, subject and author
- the right side of the single bottom status line shows workdir, the Git branch and its PR, then the agent's model and effort; clicking the model or the effort opens a dropdown to change it (the agent itself is still picked in `/config`). Click the branch, press Ctrl-B or use `/branch [name]` to select a local or already-fetched remote branch; switching uses `git switch`. Git state refreshes in the background, including changes made outside `v`;
- PR discovery is optional and uses `gh` for GitHub remotes. One PR is displayed directly; multiple PRs get a dropdown (click it or press Ctrl-P). `/pr <URL>` links any forge's PR to the current branch through local Git config (`branch.<name>.v-pr`); `/pr <number>` works for GitHub remotes. `/pr auto` removes the explicit link and returns to automatic selection. Git and manual URL links work without `gh`; `/pr` on a GitHub PR opens a read-only screen: a Conversation entry (description, reviews, comments) and the PR's files on the left, the selected file's diff on the right with inline review comments under their lines; the header's Files/Comments dropdown, left of the view-mode one (Ctrl-L or a click), switches what the left list shows: files or review threads. Threads are drawn as boxes with their state (resolved, outdated, pending), replies under the first message and Markdown bodies; the diff has a gutter of new-file line numbers. By default what you write here waits in **your pending review** on GitHub (visible only to you): replies and comments on lines or ranges are added to it and show with a `pending` badge, and the Conversation button becomes **Review summary** (the text of the review; GitHub cannot hold a plain PR comment as pending). The header's **Submit [N]** button (or Ctrl-S) shows how many comments wait and opens a menu under it: **Comment**, **Approve**, **Request changes** (needs a summary) or **Discard the pending review**; submitting publishes everything as one review with your summary. `/config` → *Comments on the PR screen* switches to publishing each comment immediately. The agents' `/review` and `/apply` use the same pending review. Your own comments have a ✕ at the right of their header: click it, then click it again to delete the comment from GitHub (any other click or key cancels, and a delete cannot be undone). Comment bodies sit on a tinted block. Every thread has clickable **Reply** and **Resolve**/**Unresolve** buttons (the state flips at once and flips back if GitHub refuses); clicking a diff line writes a comment on that line, and clicking another line while it is open stretches the comment into a range from the first line clicked (the lines it will cover are highlighted; you can also type `100-120 text`; both ends must be in one hunk). Existing multi-line threads show a `lines 100–120` badge and a bar in the gutter along the lines they cover, an open thread in the accent color and a resolved one muted, and the Conversation entry has a **New comment** button. Keyboard: Ctrl-R replies to the selected thread, Ctrl-E resolves it, Ctrl-N writes a new comment (on the selected file as `<line> <text>`, or on the PR itself from Conversation). Enter sends the comment to GitHub at once, Esc cancels; typing in the omnibox searches it, and `gh` is required. With several PRs and no explicit link, `/pr` first opens the dropdown to choose one
- `/apply` (experimental) opens an **apply screen**: a fresh agent, separate from your chat, gets the open (unresolved) review threads of this branch's PR and does the whole round: it fixes the code, verifies the build and tests with the project's own commands, commits in logical pieces on the current branch, pushes, then replies in each thread and resolves the ones it addressed. The working tree must be at the PR head (or have it in its history). The agent works with the filesystem, git and the shell itself; its only handle on GitHub is v's `pr_*` tools (`pr_description`, `pr_threads`, `pr_checks`, `pr_reply`, `pr_resolve`), and it is told not to use `gh`, not to force-push, and to treat the thread text as other people's words. You can guide it while it works (a note reaching it with its next tool result) and after it finishes (a new turn); Esc leaves, your chat comes back, and its agent is told that a separate run touched the repository. `/config` → *Apply mode*: **Manual** (default) asks about every edit and command as usual and about each reply and resolution, with the thread's code and what it says on the card; **Auto** lets the agent do everything on its own and finish the round, with one rule that still holds: a force push is refused. On the `/pr` screen an open thread has an **Apply** button (and Ctrl-A) that hands over just that thread. Claude Code only; Codex does not take part
- `/review make` (experimental) opens a **review screen**: a separate conversation with a fresh Claude Code agent that reviews this branch's GitHub PR, shown where the chat is. Esc leaves it (stopping the agent if it is still working) and your own chat comes back as it was; while it is open you can type to guide the agent, also after it has finished. The agent reads the code from your working tree, which must be at the PR head, with Read, Grep, Glob and read-only git; it has no GitHub access except v's `pr_*` tools, served by a small MCP server inside v: `pr_description`, `pr_threads` (all, resolved, unresolved, pending or rejected, including its own proposals), `pr_checks`, and the writes, which only *propose*: `pr_comment` (one line, or a range with `start_line`) and `pr_reply`. Its thinking and the files it reads stream in, and each proposal arrives as a card: the numbered diff around the line with a bar along the lines it covers and the comment right under them, marked with a bold `!!` critical (bug, data loss, security), `!` strongly recommended (design, readability, maintainability) or unmarked (an optional remark). The reviewer is told to report only what matters and to skip trivia. `/config` → Review mode: *Manual* holds the reviewer's tool call until you answer in a choice menu (↑↓ and Enter, or `y`/`n`/`a` accept the rest/`x` stop; Tab adds a note that goes to Claude with your answer; a rejected comment is not reposted); what you accept is published as one review when the agent's turn ends. *Auto* accepts everything and keeps it as a **pending** review that only you can see (later turns add to it). A message typed while the agent works reaches it with its next tool result. `/review make` starts the review, a bare `/review` says whether you have a pending review and how many comments it holds, `/review submit` publishes it, `/review discard` deletes it
- files are editable in every view mode: Enter or a click starts editing, Ctrl-S saves, Ctrl-Z / Ctrl-Y undo and redo, Esc stops; in diffs the working copy side is editable and the whole file is shown while editing;
- Flat, Unified diff and Side-by-side against git `HEAD` are always available in the top-right dropdown (Ctrl-T or a click; Tab also works in a file). Outside a file, the selection sets the next file's view. Files without Git history are shown flat;
- the single bottom status line keeps agent information and context controls. In a file it offers Edit, Save and Back; while editing, Save, Undo, Redo and Done;
- screens stack up: Esc goes back one screen, down to the chat;
- `/config` edits `~/.v/settings.json`; for now it picks the color theme. Built-in themes are One Dark Pro (+ Darker), One Light and GitHub Dark/Light; any VS Code theme JSON dropped into `~/.v/themes/` shows up too;
- `/config` also sets the diff context: how many unchanged lines show before and after each change (default 3 and 3, `diff_before` / `diff_after` in `settings.json`). It applies to every diff: file views, agent proposals, commits in `/show` and PRs in `/pr`; the PR patch comes from GitHub with 3 lines of context, so a PR can be trimmed below that but not widened;
- the agent is Claude Code or Codex, picked in `/config` with its model and effort (Codex lists its models itself). Codex runs through `codex app-server` on your ChatGPT login, in a read-only sandbox: reads go through, edits and writing commands ask;
- `v` connects to the agent at launch; anything typed without `/` goes to it (`claude -p`, signed in with your Claude subscription; `ANTHROPIC_API_KEY` is ignored). The model and effort are set in `/config` (Opus 5.5, high by default); a change applies from the next message and keeps the conversation. Replies stream into the chat as rendered markdown, and Ctrl-O shows the model's thinking; every file edit the agent proposes opens as a diff (Unified, Side-by-Side or Flat) with Yes / Edit first / No (↑↓ and Enter, or y / e / n); Tab adds a note that goes with the answer; with Edit first you change the proposal and Ctrl-S saves your version, and the agent is told what you changed. Other tool calls ask Yes / No. Esc interrupts; messages typed while the agent works are queued;
- ↑↓ in the omnibox walk through what you typed before (kept in `~/.v/history`); with some text typed, only lines starting with it;
- `/resume` lists past Claude Code sessions of this directory (yours from the terminal too) and continues the chosen one with its chat;
- `/reset` starts over with a fresh splash; `/q`, `/quit`, or Ctrl-D / Ctrl-C twice exits.

## Build

Requires Go 1.27+ and a truecolor terminal (iTerm2, Ghostty, WezTerm, Kitty).

```sh
make build   # go build -o v .
make run     # build and start
make lint    # golangci-lint (brew install golangci-lint)
```

Or install into `$GOPATH/bin`:

```sh
go install github.com/dasimagin/v@latest
```

Quit with `/q` or press `Ctrl-D` twice.
